## 📌 Project Description

**RetailPulse** is a portfolio-level, end-to-end Data Analytics and Business Intelligence project simulating a real-world multi-category Indian retail company. It covers the complete analytics pipeline — from raw data generation and cleaning through SQL analysis, Python-based customer and inventory analytics, statistical forecasting, and a 5-page Power BI executive dashboard.

The project answers concrete business questions:
- Which product categories and individual products are driving revenue vs. profit?
- Which customers are high-value, at-risk, or churning?
- Which stores are underperforming relative to their region?
- Which products face stockout risk or are slow-moving?
- What revenue trends are seasonal, and what to expect next quarter?

## 📂 Dataset

> **Note:** This project uses a **synthetically generated dataset** — no external source required.

The dataset is generated by running `python python/data_generation.py` (or executing **Section 1** of the Jupyter notebook). It produces 6 CSV files totalling ~601,000 rows:

| Table | Rows (approx.) | Description |
|-------|----------------|-------------|
| customers | 15,000 | Customer master — demographics, city, region |
| products | 600 | Product catalog — category, cost, price, stock |
| stores | 40 | Store master — city, region, type |
| orders | 150,000 | Order header — channel, status, payment method |
| order_details | 316,000 | Line items — product, quantity, unit price, discount |
| inventory_transactions | 120,000 | Stock IN/OUT/ADJUSTMENT movements |

**Data period:** January 2021 – December 2023  
**Geography:** 20 Indian cities across 5 regions (North, South, East, West, Central)  
**Categories:** Electronics, Computers & Accessories, Mobile Accessories, Home Appliances, Furniture, Clothing, Footwear, Grocery, Beauty & Personal Care, Sports & Fitness

## 🚀 Setup & Run Instructions

### Prerequisites
- Python 3.10+
- pip
- (Optional) MySQL 8.0 for SQL analytics
- (Optional) Power BI Desktop for the dashboard

### 1. Clone the Repository
```bash
git clone https://github.com/yourusername/RetailPulse.git
cd RetailPulse
```

### 2. Install Dependencies
```bash
pip install -r requirements.txt
```

### 3. Option A — Run the Jupyter Notebook (Recommended)
```bash
jupyter notebook YourName_RetailPulse.ipynb
```
Execute cells top-to-bottom. The notebook covers all 5 pipeline stages end-to-end.

### 4. Option B — Run Individual Python Scripts
```bash
python python/data_generation.py   # Step 1: Generate raw data → data/raw/
python python/data_cleaning.py     # Step 2: Clean data → data/processed/
python python/eda.py               # Step 3: EDA charts → reports/figures/
python python/rfm_analysis.py      # Step 4: RFM → data/processed/customer_rfm.csv
python python/forecasting.py       # Step 5: Forecast → data/processed/forecast.csv
```

### 5. Load into MySQL (Optional)
```sql
-- In MySQL Workbench or CLI:
SOURCE sql/schema.sql;
CALL sp_populate_dim_date('2020-01-01', '2024-12-31');
-- Then use LOAD DATA INFILE or MySQL import wizard to load data/processed/ CSVs
```

### 6. Run SQL Analytics (Optional)
Execute each `.sql` file in the `sql/` folder via MySQL Workbench.

### 7. Open Power BI Dashboard (Optional)
Open `powerbi/RetailPulse.pbix` in Power BI Desktop and update data source paths to `data/processed/`.

## 📊 Key Insights

1. **Total 3-year revenue: Rs.1,170 Crore** at 22.4% overall gross margin (Rs.202 Cr profit)
2. **Electronics + Mobile Accessories** drive ~38% of revenue but carry the lowest margins (~15–18%)
3. **Champions (21% of customers) generate 56% of total revenue** — retention is the #1 business priority
4. **October–November (Diwali)** produces 1.5–1.65× the monthly revenue average — inventory pre-loading critical
5. **12–15 high-demand SKUs** face imminent stockout (< 7 days of stock) while simultaneously at peak demand
6. **At Risk + Lost customers = 31% of base** — targeted win-back campaigns can recover significant revenue
7. **Holt-Winters forecast MAPE: 1.17%** on the 6-month hold-out test — highly accurate seasonal model
